## Проверка BOM

`bslSource.test.ts`, 0024: первоначально тест ошибочно требовал включать служебный UTF-8 BOM в `snapshot.text`. По уточнению пользователя проверка исправлена с учётом разрешённого контрактом ID-001-04-0014 чтения через `TextDocument.getText()`: снимок точно соответствует тексту документа и сохраняет CRLF, а байты файла, включая BOM, не меняются при чтении. После сохранения правки проверяются наличие BOM в файле, новая версия снимка, соответствие тексту документа и отсутствие изменений файла от повторного чтения. Production-код не изменён.

## Границы подтверждения

Тесты реестров, Engine, Store, Scheduler и Problems выполняют настоящие компоненты. Для Planner, Events, ProjectSource и MetadataSource загрузчик `loadSubject.ts` исполняет неизменённый исходник в том же Extension Host, подменяя указанные внешние зависимости. Это тестовый способ внедрения зависимостей при запрете менять production-код; он не является новым раннером.

Реальная JVM, платформа 1С и MCP не используются. Входные деревья минимальны и синтетические; происхождение описано в README фикстур. Для metadata проверены пути Конфигуратора, расширения и EDT, read-only операции, DTO, ошибки, отмена и резервный обход внешнего объекта.

Настройки и обнаружение проектов проверяются с управляемыми ответами внешних API: фактическое разрешение приоритетов настоящего multi-root workspace самим VS Code отдельно не подтверждено. Сигналы событий управляемые, доставка событий реальной файловой системой не проверяется. Linux/macOS и UNC-пути в этом прогоне не проверялись; symlink проверяется при доступности операции ОС. Полную приёмку ID-001-12-0070 считать успешной нельзя из-за ошибок typecheck.
