# 08 - Настройки и конфигурационные снимки

## Модель конфигурации

**ID-001-08-0001** - Все пользовательские настройки принадлежат существующему расширению и используют префикс `1c-platform-tools.codeStyle.*`. Не регистрировать отдельный ключ `package.json` для каждого нового ruleId; индивидуальные настройки хранятся в общем словаре `rules`.

**ID-001-08-0002** - Для Task #1 определить общие ключи: `enabled` (по умолчанию true), `scanOnSave` (true), `maxConcurrency` (2, допустимый диапазон 1..8), `categories` (объект category -> boolean) и `rules` (объект ruleId -> {enabled?,severity?,options?}). Конкретная JSON Schema в `package.json` разрешает будущие имена правил без правки манифеста.

**ID-001-08-0003** - `SettingsProvider` читает `vscode.workspace.getConfiguration('1c-platform-tools', vscode.Uri.file(projectRoot))` или эквивалентный context-aware вызов. Приоритеты настроек задаются самим VS Code: folder/workspace/user; не создавать вторую несогласованную систему разрешения.

**ID-001-08-0004** - `enabled=false` запрещает новые запуски и немедленно убирает issues из активной выдачи. `scanOnSave=false` отключает автоматическое назначение сканирования по сохранённым или внешним изменениям исходников, но не отключает инвалидацию старых результатов и будущие явные ручные запуски.

**ID-001-08-0005** - `categories[category]=false` имеет приоритет над включением отдельных правил категории. Иначе индивидуальное `rules[ruleId].enabled` перекрывает `defaultEnabled`; отсутствующий override означает использование default из RuleDefinition.

**ID-001-08-0006** - `severity` допускает `error`, `warning`, `information`, `hint`; отсутствие переопределения означает `defaultSeverity`. Отключение правила задаётся `enabled`, не выдуманным severity `off`.

**ID-001-08-0007** - `options` содержит только объявленные RuleDefinition параметры с проверкой типа/границ и default-значениями. Не делать специальных веток для известных ruleId в SettingsProvider или package.json.

**ID-001-08-0008** - Незнакомые ruleId в `rules` не являются реальными проверками и не вызывают их создание. Хранить неиспользуемую запись настроек допустимо, но она не должна влиять на другие определения.

## Версии и изменения

**ID-001-08-0009** - Для каждого запуска формировать неизменяемый эффективный снимок настроек по проекту и выбранным правилам. Нельзя перечитывать глобальное VS Code configuration во время исполнения отдельного правила.

**ID-001-08-0010** - Вычислять конфигурационную ревизию или fingerprint только из параметров, влияющих на соответствующее правило и выполнение его проверки. Изменение других правил не делает текущий результат устаревшим.

**ID-001-08-0011** - Неправильный тип общего ключа/опции или недопустимое значение надо выявлять на границе SettingsProvider с понятной технической ошибкой. Не преобразовывать сломанную конфигурацию в успешно выполненную проверку с произвольными дефолтами.

**ID-001-08-0012** - Изменение enabled/category требует инвалидировать/скрыть только затронутые issues и отменить зависимые задания. Изменение опций заново проверяет затронутые правила; изменение severity обновляет либо пересчитывает только относящиеся к нему результаты, сохраняя непричастные.

**ID-001-08-0013** - На `onDidChangeConfiguration` проверять `affectsConfiguration` ключей Code Style с учётом project folder; нельзя безусловно пересчитывать все проекты при изменении настройки одного workspace folder.

**ID-001-08-0014** - Новые параметры существующих правил получают default из определения; добавление правила не требует редактирования SettingsProvider. Не создавать миграции ключей или legacy-алиасы для ещё не выпущенной подсистемы.

**ID-001-08-0015** - Отключение фонового сканирования не делает старые результаты автоматически актуальными после изменения файлов: invalidation работает независимо от schedule, чтобы Problems не показывал замечания от прежней версии.

## Граница с будущим UI/MCP

**ID-001-08-0016** - В Task #1 нет пользовательской панели, команды изменения настроек или прикладного действия `changeSettings`. Фасад может предоставлять read-only снимок и внутреннее уведомление об изменении; запись настроек должна появиться отдельным явно согласованным действием позднее.

**ID-001-08-0017** - Будущая панель и MCP должны использовать одни effective settings и правила разрешения; JSON-представление на границе транспорта не содержит `vscode.WorkspaceConfiguration`, функций или TS-синглтонов.

**ID-001-08-0018** - `maxConcurrency` управляет только планировщиком Code Style и не переписывает внутреннюю очередь md-sparrow или глобальные настройки других фич Platform Tools.
