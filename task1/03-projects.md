# 03 - Границы проектов и идентичность источников

## Обнаружение и владение файлами

**ID-001-03-0001** - Источником истины о зарегистрированных проектах является `workspaceProjects.ts` (`projectOf`, `projectByRoot`, `projectsSnapshot`, `listProjects`, `projectRootKey`); о раскладке - `projectLayout.ts` (`resolveProjectLayout`, `sameOrUnder`, `rootOfDirectory`). Линтер не сканирует workspace ради собственного поиска `packagedef`.

**ID-001-03-0002** - `projectOf(uri)` не видит `ProjectCandidate`: для поддерживаемых выгрузок без `packagedef` дополнять определение по `projectsSnapshot().candidates` или `listCandidates()` с использованием раскладки кандидата. Не создавать или модифицировать `packagedef`.

**ID-001-03-0003** - Если `projectsSnapshot().complete` равно false, не считать неполный перечень окончательным. Для тяжёлого обхода дождаться завершения штатного обнаружения или вернуть incomplete и повторить при событии изменения проектов.

**ID-001-03-0004** - При входе по URI файла разрешить наиболее конкретную допустимую границу среди зарегистрированных проектов и кандидатов. Кандидат вложенной конфигурации не должен поглощаться корнем родителя; исключить каталоги более глубоких подпроектов.

**ID-001-03-0005** - При явной проверке проекта фиксировать нормализованный root в контексте запуска и передавать его через асинхронную цепочку. Не использовать `currentRoot()` для назначения проекта изменённого файла; пользователь может переключить выбор во время анализа.

**ID-001-03-0006** - Неизвестный, внешний или неоднозначный файл возвращает управляемую ошибку области/источника, не переводится автоматически в первый workspace folder. Для URI с не-файловой схемой не применять `fsPath` и файловые API без явно поддержанного поставщика.

## Разделение проекта и источника

**ID-001-03-0007** - Одна рабочая область может содержать основную конфигурацию, несколько расширений, внешние обработки/отчёты и подпроекты. `projectKey` задаёт владение жизненным циклом, `sourceKey` различает каждый из этих исходных корней, `targetKey` идентифицирует BSL-файл или metadata-объект.

**ID-001-03-0008** - Формировать sourceKey из канонического источника раскладки (тип, формат и нормализованный путь корня), а не только из его видимого названия. Одноимённые расширения в разных проектах не должны объединяться.

**ID-001-03-0009** - Для выгрузок 1C:Конфигуратор использовать корни конфигурации/расширений/внешних объектов из `ProjectLayout`; для 1C:EDT учитывать, что source root может быть корнем EDT-проекта, а исходники расположены в его `src`.

**ID-001-03-0010** - `ProjectLayout.others`, `extensions`, `testExtensions`, `processors`, `reports`, `testProcessors` и `externals` нельзя молча игнорировать при определении доступных источников. Не включать сам подпроект в обход родителя после того, как он выделен отдельной границей.

**ID-001-03-0011** - При смене типа, состава и границ проектов существующие sourceKey и targetKey сверяются с новым снимком; результаты исчезнувших источников удаляются/инвалидируются только после достоверного обновления перечня, без стирания независимых проектов.

**ID-001-03-0012** - `projectScanRoots()` и `ProjectLayout` предоставляют допустимые корни и исключения; использовать их назначения раздельно. Правила исключения **поиска проектов** не являются списком исключений для BSL-модулей: каталог `Ext` содержит реальный код `Module.bsl` и должен оставаться доступным BSL-поставщику.

## Пути, безопасность, активация

**ID-001-03-0013** - При сравнении файловых корней использовать штатные `projectRootKey`/`directoryKey`/`sameOrUnder` и `path.relative`, проверять границы сегментов пути; проверка строковым `startsWith` запрещена. На Windows учитывать регистр и UNC, на Linux/macOS не выполнять безусловный lowercase.

**ID-001-03-0014** - Для найденной цели резолвить относительный путь строго относительно разрешённого корня и проверять, что нормализованный абсолютный путь остаётся внутри него. Для символических ссылок и реального чтения предотвращать выход за доверенную область; при невозможности подтвердить безопасность - пропустить источник с технической ошибкой.

**ID-001-03-0015** - Не подменять исходные source roots общим корнем рабочего пространства ради удобства glob. Все операции enumerate/read используют границы своего проекта и source; ограничения и исключения из `ProjectLayout` не должны обходиться поиском `**/*.bsl` по всему окну.

**ID-001-03-0016** - При удалении проекта из workspace удалять только результаты его projectKey и освобождать связанные задачи. Переключение текущего проекта не очищает другие проекты: Problems показывает их все, а будущий UI сможет фильтровать.

**ID-001-03-0017** - Отдельные выгрузки без `packagedef` могут не активировать расширение по текущим `activationEvents`. Проверка и необходимые минимальные изменения условий активации описаны в `11-integration.md`; не вводить глобальную активацию без фактической необходимости.

**ID-001-03-0018** - Для OneScript-пакетов без исходных BSL/metadata объектов линтер не придумывает фиктивные источники. Отсутствие применимых source roots не равно ошибке, но неполный обход или недоступность ожидаемых корней должны явно отражаться в результате.
