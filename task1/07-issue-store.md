# 07 - IssueStore, фиксация и выдача замечаний

## Владение состоянием и индексы

**ID-001-07-0001** - `IssueStore` является in-memory источником истины для замечаний текущего окна VS Code, отдельно от `DiagnosticCollection`, технических логов, интерфейсов панели и MCP. Дисковое постоянное хранилище и миграции схемы в Task #1 не создавать.

**ID-001-07-0002** - Основной адрес сохранения - `projectKey -> ruleId -> targetKey -> issues`, где targetKey относится к цели анализа, не к URI места нарушения. При необходимости sourceKey включается в состав устойчивого ключа цели.

**ID-001-07-0003** - Держать обратные индексы по URI локаций, URI исходных целей и URI прочитанных зависимостей, чтобы быстро выявлять затронутые проверки при записи, удалении, переименовании и публикации; не полагаться только на `Issue.location.uri`.

**ID-001-07-0004** - Помимо замечаний отдельно хранить актуальность каждой пары, версию исходного снимка, использованные зависимости, ревизию настроек, runId/порядок принятого результата и техническое состояние. Отсутствие issues и отсутствие успешной проверки являются разными состояниями.

**ID-001-07-0005** - `IssueStore` отвечает за окончательную сверку токена/версий и атомарный commit. Планировщик может знать, что работа устарела, но не вправе публиковать результат напрямую или обходить Store.

**ID-001-07-0006** - Приём пары должен быть атомарен относительно видимых читателям данных и событий: либо новый набор полностью заменил предыдущий, включая пустой набор, либо все данные прежней версии остались без частичного смешивания.

## Протокол частичного commit

**ID-001-07-0007** - Каждое сохранение получает `CommitTicket` с projectKey, ruleId, targetKey, runId, исходной версией, зависимостями, ревизией настроек и порядком запуска. Store сверяет эти значения с текущим состоянием конкретной пары перед записью.

**ID-001-07-0008** - Успешная проверка пары (ruleId,targetKey) полностью заменяет старые замечания этой пары; успешный пустой массив удаляет её прежние замечания. Это единственный нормальный способ получить «0 замечаний» после выполненного check.

**ID-001-07-0009** - Ошибка чтения, исключение правила, отмена, неподдерживаемая цель или устаревший ticket не заменяют замечания пустым результатом. Их состояние становится incomplete/stale/error, а активная выдача больше не представляет устаревшее как актуальное.

**ID-001-07-0010** - Состояния других projectKey, ruleId и targetKey от частичного commit не изменяются. Ошибка одного правила на объекте не удаляет результат другого успешно проверенного правила на том же объекте.

**ID-001-07-0011** - Если новая частичная проверка уже зафиксировала результат пары, старый full-run не имеет права его перезаписать при той же или более старой версии. Сравнивать логический порядок на уровне пары, а не отменять все другие результаты глобальным epoch.

**ID-001-07-0012** - Любые изменения зависимостей, настройки правила, версии исходника или принадлежности project/source между чтением и commit приводят к отказу принять этот ticket; операция не публикует событие о новых актуальных замечаниях.

**ID-001-07-0013** - При изменении target или dependency до пересчёта немедленно пометить его прежние issues как stale и исключить из стандартной активной выдачи. Хранить stale для будущей диагностики допустимо, но такие записи нельзя выдавать за актуальные.

**ID-001-07-0014** - Если ранее применимое правило перестало соответствовать цели после смены фильтра/настроек, его результаты должны исчезнуть из активной выдачи и быть удалены при достоверно полном пересчёте выбранного scope; простое `supportsTarget=false` без учёта инвалидации не оставляет активную старую ошибку.

## Полный обход, удаление и проекты

**ID-001-07-0015** - Для финальной очистки при full-run требуется одновременно: полный enumerate соответствующих исходников, актуальный `inventoryRevision`, зафиксированный набор проверенных ruleId/sourceKind и подтверждение, что состав целей не изменился с начала обхода.

**ID-001-07-0016** - Полная очистка ограничена перечисленными projectKey, ruleId и видами источников; она не удаляет замечания невыбранных правил, других проектов, неподдерживаемых либо не полностью обойдённых source roots.

**ID-001-07-0017** - Если full-run не завершил перечисление или список устарел, Store может принять отдельные успешные актуальные пары, но не выполнять массовое удаление непосещённых целей. Не выводить отсутствие объекта из ошибки его чтения.

**ID-001-07-0018** - Подтверждённое удаление target очищает его замечания независимо от завершения новой проверки; удалённый URI исчезает из индексируемых актуальных locations. При rename очищаются старые цель/URI, а новый путь получает новую идентичность или согласованный перенос после проверки.

**ID-001-07-0019** - При удалении проекта из workspace удаляются данные только его projectKey и отменяются связанные запуски. Смена выбранного текущего проекта не означает удаления других projectKey.

**ID-001-07-0020** - Выключение линтера или правила/категории сразу скрывает соответствующие замечания; включение не воскрешает старые записи как актуальные без проверки или подтверждения совпадения снимков. Изменение severity не должно затрагивать другие правила.

## Запросы и события

**ID-001-07-0021** - `getIssues(filter)` возвращает по умолчанию только текущие актуальные замечания, поддерживает отбор по проекту, конфигурации/расширению, файлу/target, ruleId, area, category, severity и явно запрошенному статусу.

**ID-001-07-0022** - Результат выдачи сортируется стабильно: projectKey, URI, строка, символ, ruleId, issueId. Для внешних потребителей возвращать immutable/копии DTO, не позволять мутировать внутренний Store.

**ID-001-07-0023** - Вместе с найденными issues доступна служебная сводка по полноте, статусам целей и техническим ошибкам, чтобы агент не принимал пустой ответ неполного сканирования за «нарушений нет». Ошибки не добавлять как пользовательские Issues.

**ID-001-07-0024** - По изменениям Store генерирует события с перечнем затронутых URI/проектов/правил и причиной (commit, invalidate, remove, settings). Publisher использует эти сигналы для точечной пересборки, не подписывается на работу Engine напрямую.

**ID-001-07-0025** - Не реализовывать в Task #1 курсорную пагинацию, постоянную БД или отдельные копии индексов ради будущего UI/MCP. Если последующим интерфейсам потребуется лимит выдачи, он добавляется поверх одного getIssues-контракта.

**ID-001-07-0026** - На dispose очищать индексы, события и память; запоздалый commit после dispose отклонять. Исключения подписчика не должны приводить к частично принятому состоянию Store.
