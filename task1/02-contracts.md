# 02 - Контракты и модель данных

## Независимые классификации

**ID-001-02-0001** - `RuleArea` имеет значения `bsl`, `metadata`, `forms`, `queries`, `rights`; `RuleCategory` имеет `style`, `metadata`, `performance`, `security`, `reliability`, `compatibility`. Эти множества фиксированы для Task #1; одинаковое значение `metadata` не означает общей сущности.

**ID-001-02-0002** - `SourceKind` описывает природу проверяемых данных: BSL-модуль, объект метаданных, форма, фрагмент запроса, права. Не определять его автоматически только по суффиксу файла; поставщик обязан вернуть явно согласованный вид источника.

**ID-001-02-0003** - Для source/target различать `projectKey` (границы проекта или кандидата), `sourceKey` (конфигурация, расширение либо внешний объект) и `targetKey` (конкретная проверяемая сущность). Ключи нормализованы, не зависят от выбранного в UI текущего проекта и однозначны внутри workspace.

**ID-001-02-0004** - Краткий `TargetDescriptor` содержит ключи, sourceKind, путь для навигации, принадлежность, формат при необходимости и доступные дешёвые признаки (например `objectType` для metadata). Подробный текст модуля или DTO свойств в descriptor не помещать.

**ID-001-02-0005** - `ScanScope` определяет, что обследовать (проект, список файлов/целей, виды источников и набор правил); `IssueFilter` определяет, какие сохранённые замечания вернуть (проект/конфигурация, файл/цель, area, category, ruleId, severity, актуальность). Не подменять scope фильтром выдачи.

## Контракт определения правила

**ID-001-02-0006** - `RuleDefinition` содержит стабильный уникальный `id` в kebab-case, `title`, `description`, `area`, `category`, `defaultSeverity`, `defaultEnabled`, поддерживаемые `SourceKind`, описание/значения по умолчанию настроек, `check(context)` и необязательный контракт будущего `fix`.

**ID-001-02-0007** - Необязательный `supportsTarget(descriptor)` является чистым синхронным предикатом по дешёвым свойствам цели. Он не читает файлы, не создаёт JVM, не изменяет состояние и не может запрашивать детальный DTO. Отсутствие предиката означает применимость к любой цели указанного SourceKind.

**ID-001-02-0008** - `check(context)` возвращает массив замечаний либо Promise массива; правила не имеют прямого доступа к VS Code Problems, IssueStore, глобальным настройкам, UI или механизмам записи файлов. Исключение правила должно изолироваться от других правил.

**ID-001-02-0009** - `RuleContext` фиксирует проект, source, descriptor, эффективные настройки конкретного правила, признак версии, сигнал отмены и ограниченный read-only доступ к подготовленному содержимому и при необходимости связанным источникам того же проекта.

**ID-001-02-0010** - Чтение содержимого через RuleContext должно быть ленивым и разделять результат между правилами одной цели: правило, которому достаточно descriptor, не должно инициировать `cf-md-object-get` или чтение полного BSL. Запрос содержания возвращает согласованный снимок либо явную ошибку, но не выдуманные пустые данные.

**ID-001-02-0011** - Если правило читает связанные источники, контекст ограничивает чтение тем же разрешённым проектом, регистрирует зависимости и версии. Обновление любого использованного источника инвалидирует зависящий результат; не предоставлять бесконтрольный доступ к файловой системе.

## Замечания и координаты

**ID-001-02-0012** - `Issue` включает стабильный `id`, `ruleId`, area, category, эффективную severity, сообщение, принадлежность проекту/source/target, версию снимка, основную локацию и при необходимости related locations, а также необязательные сведения об исправляемости **данного замечания**.

**ID-001-02-0013** - `IssueLocation` содержит реальный файловый URI и полуоткрытый диапазон VS Code с нумерацией строк и символов от нуля. Валидировать неотрицательные координаты и порядок границ; некорректная локация является ошибкой результата правила.

**ID-001-02-0014** - Отдельно хранить цель анализа, версию прочитанных исходных данных и местоположение нарушения. Одна metadata-цель может указывать на файл объекта, а замечание запроса - на BSL-диапазон; расположение не определяет адрес замены в IssueStore.

**ID-001-02-0015** - Если md-sparrow не знает точного диапазона свойства, указывать существующий файл и безопасную начальную позицию, пояснив путь метаданных в сообщении. Не фабриковать координаты несуществующего файла или не выдавать предположительную строку за точную.

**ID-001-02-0016** - `Issue.id` формируется детерминированно из проекта, правила, цели и устойчивого якоря нарушения; две одинаковые находки в одной цели получают разные идентификаторы. Нельзя использовать один лишь номер строки или случайный UUID при каждом запуске.

**ID-001-02-0017** - `relatedLocations` допустимы для дополнительных файлов, но только с проверенной принадлежностью, реальными URI и корректными диапазонами. Изменение связанного файла должно сделать ранее опубликованную диагностику недействительной, если замечание зависит от этого файла.

**ID-001-02-0018** - Отсутствующая информация об исправлении означает «автоисправление не предлагается» независимо от наличия `fix` в определении правила. В Task #1 нет исполнения исправлений, вычисления патчей или записи BSL/XML/MDO.

## Результат запуска и переносимость

**ID-001-02-0019** - `ScanResult` должен раздельно описывать запрошенную и действительно проверенную область, runId, полноту, статус, количество текущих замечаний, список успешно обработанных целей и технические ошибки. Не судить об успешности по пустому массиву.

**ID-001-02-0020** - Статусы различают как минимум: успешно и полностью, успешно лишь часть, нет применимых правил, отменено, устарело, ошибка и неподдерживаемый источник. Конкретные названия TS-discriminant выбирает реализация, но эти состояния должны быть непересекающимися в семантике.

**ID-001-02-0021** - `SourceVersion`/`SettingsRevision`/`InventoryRevision` представляют отдельные признаки актуальности: версия прочитанных данных, настройки выбранных правил и состав целей полного обхода. Их нельзя заменять одним глобальным epoch всего расширения.

**ID-001-02-0022** - Внутренние типы могут содержать `vscode.Uri` и `CancellationToken`, но DTO на будущей границе ActionDispatcher/панель/MCP должны быть JSON-совместимыми: строки URI, обычные значения, без функций, классов VS Code и Error-объектов.

**ID-001-02-0023** - Технические ошибки сохранять в состоянии запуска/цели, не превращать в Issue пользователя. Все виды ошибок оформляются единым контрактом с кодом и безопасным сообщением; stack trace остаётся только в logger.
